## What is GitOps?

GitOps is an operational paradigm where Git serves as the **single source of truth** for infrastructure and applications. Instead of executing imperative commands, you declare the desired state in versioned files in Git.

<Callout type="info" title="GitOps Principles">
  1. **Declarative**: The entire system is described declaratively
  2. **Versioned**: The desired state is in Git
  3. **Automated**: Approved changes are applied automatically
  4. **Reconciliation**: Software ensures continuous convergence
</Callout>

## ArgoCD: The Community Favorite

ArgoCD is the most popular GitOps tool, with a rich UI and large ecosystem.

### ArgoCD Architecture

```yaml
# Main components
components:
  api-server:
    description: REST and gRPC API, serves UI and CLI

  repo-server:
    description: Clones Git repos, generates manifests

  application-controller:
    description: Monitors apps, executes reconciliation

  dex:
    description: SSO authentication (OIDC, LDAP, GitHub)

  redis:
    description: Cache for performance
```

### ArgoCD Installation

```bash
# Create namespace
kubectl create namespace argocd

# Install ArgoCD
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# Get initial admin password
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d

# Port forward to access UI
kubectl port-forward svc/argocd-server -n argocd 8080:443
```

### Defining an Application

```yaml
# application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://github.com/myorg/my-app-config
    targetRevision: main
    path: k8s/overlays/production

  destination:
    server: https://kubernetes.default.svc
    namespace: my-app

  syncPolicy:
    automated:
      prune: true        # Remove resources not in Git
      selfHeal: true     # Automatically corrects drift
    syncOptions:
      - CreateNamespace=true
      - PruneLast=true
```

### ApplicationSet for Multi-Cluster/Multi-Env

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: my-app-set
  namespace: argocd
spec:
  generators:
    - list:
        elements:
          - cluster: staging
            url: https://staging.k8s.example.com
          - cluster: production
            url: https://prod.k8s.example.com

  template:
    metadata:
      name: 'my-app-{{cluster}}'
    spec:
      project: default
      source:
        repoURL: https://github.com/myorg/my-app-config
        targetRevision: main
        path: 'k8s/overlays/{{cluster}}'
      destination:
        server: '{{url}}'
        namespace: my-app
```

## FluxCD: CNCF Native GitOps

FluxCD is the more "cloud-native" alternative, using Kubernetes CRDs for everything.

### FluxCD Architecture

```yaml
# Flux Controllers
controllers:
  source-controller:
    description: Manages sources (Git, Helm, OCI)

  kustomize-controller:
    description: Reconciles Kustomizations

  helm-controller:
    description: Reconciles HelmReleases

  notification-controller:
    description: Events and alerts

  image-automation-controller:
    description: Automatically updates images
```

### FluxCD Bootstrap

```bash
# Install Flux CLI
curl -s https://fluxcd.io/install.sh | sudo bash

# Bootstrap with GitHub
flux bootstrap github \
  --owner=myorg \
  --repository=fleet-infra \
  --branch=main \
  --path=clusters/production \
  --personal
```

### Defining Resources in Flux

```yaml
# GitRepository - source
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 1m
  url: https://github.com/myorg/my-app-config
  ref:
    branch: main
---
# Kustomization - what to deploy
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 10m
  targetNamespace: my-app
  sourceRef:
    kind: GitRepository
    name: my-app
  path: ./k8s/overlays/production
  prune: true
  healthChecks:
    - apiVersion: apps/v1
      kind: Deployment
      name: my-app
      namespace: my-app
```

### Image Automation (Flux unique feature)

```yaml
# ImageRepository - monitor registry
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImageRepository
metadata:
  name: my-app
  namespace: flux-system
spec:
  image: ghcr.io/myorg/my-app
  interval: 1m
---
# ImagePolicy - which tag to use
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImagePolicy
metadata:
  name: my-app
  namespace: flux-system
spec:
  imageRepositoryRef:
    name: my-app
  policy:
    semver:
      range: ">=1.0.0"
---
# ImageUpdateAutomation - automatic commit
apiVersion: image.toolkit.fluxcd.io/v1beta2
kind: ImageUpdateAutomation
metadata:
  name: my-app
  namespace: flux-system
spec:
  interval: 30m
  sourceRef:
    kind: GitRepository
    name: fleet-infra
  git:
    checkout:
      ref:
        branch: main
    commit:
      author:
        name: fluxcdbot
        email: flux@example.com
      messageTemplate: 'chore: update {{.AutomationObject.Name}} to {{.NewImage}}'
    push:
      branch: main
  update:
    path: ./clusters/production
    strategy: Setters
```

## Comparison: ArgoCD vs FluxCD

| Aspect | ArgoCD | FluxCD |
|--------|--------|--------|
| **UI** | ✅ Rich and interactive | ❌ CLI/API only |
| **Learning Curve** | Easier | More CRDs to learn |
| **Multi-tenancy** | Projects | Namespaced controllers |
| **Image Automation** | Via plugin | ✅ Native |
| **Helm** | ✅ Native | ✅ Native |
| **Kustomize** | ✅ Native | ✅ Native |
| **SSO/RBAC** | ✅ Integrated Dex | Via Kubernetes RBAC |
| **Resources** | Heavier | Lighter |
| **CNCF** | Graduated | Graduated |

<Callout type="success" title="Our Recommendation">
  **ArgoCD** for teams that need a visual UI and are starting with GitOps. **FluxCD** for teams that prefer a 100% declarative approach and are already proficient in Kubernetes.
</Callout>

│       ├── infrastructure.yaml

│   ├── base/

│   │   └── monitoring/
│   └── overlays/

    ├── base/

    └── overlays/

            └── kustomization.yaml
